= Multi-Cluster Virtualization with OpenShift

== Introduction

The Multi-Cluster section covers advanced virtualization capabilities for managing virtual workloads across multiple OpenShift clusters. This includes cross-cluster live migration (CCLM), cluster synchronization, and integration with Red Hat Advanced Cluster Management (ACM) for centralized governance and workload management at scale.

These capabilities enable organizations to:

* Migrate VMs between geographically distributed clusters
* Maintain application continuity across cluster boundaries
* Implement disaster recovery and business continuity strategies
* Centrally manage virtualization policies across multiple clusters
* Optimize workload placement across a multi-cluster infrastructure

* Cross-Cluster Live Migration (CCLM) concepts and architecture
* Implementing CCLM between OpenShift Virtualization clusters
* Integrating CCLM with Red Hat Advanced Cluster Management

== Key Concepts

=== Sync Controllers
Controllers deployed on each cluster that synchronize cluster state and enable communication for multi-cluster operations. Essential for CCLM functionality.

=== Cross-Cluster Live Migration (CCLM)
The process of moving a running VM from one OpenShift Virtualization cluster to another without stopping the guest OS. Requires shared storage and network connectivity.

=== Migration Toolkit for Virtualization (MTV)
Red Hat's solution for migrating virtual machines. Includes UI and APIs for planning and executing cross-cluster migrations.

=== Provider Configuration
Setting up connections between source and destination clusters so MTV can orchestrate migrations.

=== Network Mapping
Configuring how VM network interfaces map between source and destination cluster networks.

=== Storage Considerations
Ensuring shared storage backends are accessible from both clusters to support live migration.

=== Red Hat Advanced Cluster Management (ACM)
Centralized management platform for multiple OpenShift clusters, providing policy enforcement, governance, and workload management.

=== Disaster Recovery (DR)
Using CCLM to implement automated recovery strategies for business continuity.

=== CCLM Workflow

1. **Preparation** — Verify sync controllers, configure providers and network maps
2. **Planning** — Create migration plans in MTV UI
3. **Execution** — Start migration, monitor progress
4. **Verification** — Confirm VM is running on destination
5. **Cleanup** — Remove source VM resources (optional)

[[operational_considerations]]
== Operational Considerations

=== Network Requirements
* Low-latency connectivity between clusters (typically < 100ms RTT)
* Sufficient bandwidth for VM memory and disk transfer
* Firewall rules allowing MTV communication ports
* Network maps for VM network interface translation

=== Storage Requirements
* Shared storage backends accessible from both clusters
* Sufficient capacity on destination cluster
* Consistent storage configuration between clusters
* Network accessibility and performance

=== Cluster Compatibility
* Both clusters must run compatible OpenShift versions
* OpenShift Virtualization versions should be compatible
* Cluster networking models must be compatible (SDN/OVN)
* CPU compatibility for guest VMs

=== Performance Considerations
* CCLM performance depends on network bandwidth and latency
* Memory transfer time scales with VM memory size
* Disk migration time varies by storage backend and disk size
* Minimize workload I/O during migration for faster completion
