= Core Operators for OpenShift Virtualization

== Introduction

The Core Operators section covers the essential operational features and advanced capabilities that make OpenShift Virtualization production-ready. These operators and features enable you to manage VM workloads at scale, ensure optimal resource utilization, maintain high availability, and implement sophisticated scheduling strategies.

.*What You'll Learn*

* Migrate virtual machines between nodes and storage types without downtime
* Manage CPU and memory resources across your cluster
* Dynamically add or remove VM resources without stopping the VM
* Implement node affinity and pod affinity/anti-affinity rules
* Automatically reschedule VMs based on cluster state
* Configure fencing and node health checks for failure remediation
* Scale virtual workloads across your infrastructure

.*Topics Covered*

. xref:05-live-migration.adoc[Live Migration] — Move running VMs between nodes and storage classes
. xref:06-resource-management.adoc[Resource Management] — Understand and optimize CPU/memory allocation

. xref:11-fencing.adoc[Fencing] — Configure node health checks and automatic failure remediation
. xref:07-real-world-scaling.adoc[Real World Scaling] — Scale VMs and clusters in realistic production scenarios

* Storage migration for performance optimization
* Compliance with application availability requirements

[[key_concepts]]
== Key Concepts

=== Live Migration
Moving a running VM from one node or storage backend to another without stopping the guest OS. Enables non-disruptive maintenance and workload balancing.

=== Resource Overcommit
Allocating more CPU or memory to VMs than physically exists on nodes. Useful for burst workloads but requires careful monitoring.

=== Hot-Plugging
Adding or removing hardware resources (CPU, memory, disk, NIC) to a running VM without shutdown.

=== Affinity Rules
Kubernetes scheduling constraints that influence where VMs are placed:
* **Node Affinity** — Host preference
* **Pod Affinity** — Colocation with other workloads
* **Pod Anti-Affinity** — Separation from other workloads

=== Descheduling
Post-scheduling optimization that evicts and replaces VMs to improve cluster efficiency.

=== Fencing
Automatic detection of unhealthy nodes and recovery mechanisms to maintain cluster health.

[[common_workflows]]
== Common Workflows

=== Scenario 1: Non-Disruptive Node Maintenance
1. xref:05-live-migration.adoc[Migrate VMs] off the target node
2. Perform maintenance
3. Resume normal operations with descheduler optimization

=== Scenario 2: Handling Node Failure
1. xref:11-fencing.adoc[Node health checks] detect failure
2. xref:11-fencing.adoc[Fencing] evicts VMs from failed node
3. VMs are xref:05-live-migration.adoc[automatically migrated] to healthy nodes

=== Scenario 3: Peak Load Management
1. xref:07-real-world-scaling.adoc[Monitor utilization] on running VMs
2. xref:08-hot-plug.adoc[Hot-plug] additional resources as needed
3. xref:07-real-world-scaling.adoc[Add cluster nodes] if capacity required

=== Scenario 4: Workload Optimization
1. Configure xref:09-affinity.adoc[affinity rules] for workload placement
2. Enable xref:10-descheduler.adoc[descheduler] for ongoing optimization
3. Periodically review xref:06-resource-management.adoc[resource allocation]
