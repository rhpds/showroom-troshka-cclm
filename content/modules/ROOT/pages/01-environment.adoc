= Environment

Welcome to *Beyond the Basics: Operationalizing Red Hat OpenShift Virtualization*. In this lab you practice day-to-day virtual machine operations, scale and place workloads inside a cluster, automate common tasks with Ansible Automation Platform, and finish by live-migrating a VM across two nested OpenShift clusters.

*OpenShift Virtualization* brings virtual machines onto Kubernetes-based infrastructure so you can develop and deliver new applications, modernize existing ones, and run VMs, containers, and serverless functions together with Kubernetes-native tools.

*Ansible Automation Platform* lets platform and DevOps teams create, manage, and scale automation across physical, cloud, virtual, and edge environments—driving consistency and compliance across infrastructure, networking, applications, storage, and security.

Together, these products give you a single place to host and operate the workloads in your data center.

[[whobenefits]]
== Who Will Benefit Most from Attending this Lab?

*Virtual Machine Administrators* — Responsible for day-to-day management of virtual guests in OpenShift Virtualization: provisioning VMs and operating the guests and applications that run on them.

*Virtual Infrastructure Administrators* — Responsible for the physical infrastructure that hosts OpenShift Virtualization: hardware, storage, and networking changes that affect running virtual machines.

[[contentcovered]]
== What Content is Covered in this Lab?

* _OpenShift Virtualization Fundamentals_ — Deploy, configure, and manage virtual machine state.
* _Security and Compliance_ — Run Compliance Operator scans and apply NetworkPolicies to VM traffic.
* _Day-to-Day Operations_ — Automate inventory, observability, and VM lifecycle tasks with Ansible Automation Platform.
* _Live Migration_ — Move VMs between nodes and between storage classes without downtime.
* _Resource Management_ — Overcommit CPU and memory to meet rising workload demand.
* _Real-World Scaling_ — Triage and resolve a scaling scenario under load.
* _Hot-Plug_ — Add CPU, memory, disk, and NIC to a running VM.
* _Affinity and Anti-Affinity_ — Control where VMs run for performance and availability.
* _Dynamic Scheduling_ — Use the descheduler to rebalance VM placement across the cluster.
* _Fencing and Remediation_ — Keep workloads resilient when a node fails.
* _Cross-Cluster Live Migration (CCLM)_ — Migrate a VM from the *source* cluster to the *destination* cluster with MTV.
* _Scale to the Moon_ — Discuss additional operational scenarios for OpenShift Virtualization and Ansible Automation Platform.

[[labenvironment]]
== Lab Environment

Consoles for both clusters appear in tabs on the right (*Source Console* and *Destination Console*) so you can keep instructions and the UI side by side.

This environment is provisioned by Troshka as two nested OpenShift clusters that share an external Ceph backend and a dedicated migration L2 network. Post-install configuration enables OpenShift Virtualization for *decentralized live migration*, Migration Toolkit for Virtualization (MTV), Submariner, and MetalLB so you can live-migrate a workload VM from *source* to *destination*.

== Storage

Both clusters attach to the *same* external Ceph RBD pool. Troshka exports project Ceph into each nested OpenShift Data Foundation (ODF) cluster. MTV StorageMaps target `ocs-external-storagecluster-ceph-rbd` so disks move with live migration without copying data over the migration network.
